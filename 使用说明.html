1. 启动与使用

Windows 双击项目根目录的 start.bat。默认地址为 http://127.0.0.1:8767，服务窗口保持开启。已有健康服务会被复用，不重复启动。

本机已经安装隔离虚拟环境并构建前端。迁移到新机器时，需要安装 Python 3.10–3.12 并让 python 可在命令行调用；删除迁移过来的旧 .venv，由启动器重新创建。首次安装依赖需要网络。预构建的 frontend/dist 存在时，运行不需要 Node.js。

start.bat
start.bat --no-browser
start.bat --port 8768
01 导入生成明确标注的合成数据，或上传 CSV。
02 检测选择算法、历史训练比例及阈值分位数。
03 分析选择事件、缩放时间范围、检查变量偏离。

三个导航页均为实际功能：分析工作台、数据集管理和检测历史。历史记录来自服务端持久化；刷新浏览器后可以重新打开已经完成的检测。

建议第一次使用：生成演示 → 默认 PCA → 开始异常检测 → 选择第一段事件 → 保存复核 → 导出报告。示例不是生产数据，不预填检测结果。

2. CSV 数据契约

最大 25 MiB，120–100,000 行，2–64 个有效数值变量。支持 UTF-8、UTF-8 BOM 和 GB18030。首行为不重复的列名；建议先将数据整理到固定采样频率。

timestamp,cpu_usage,memory_usage,is_anomaly
2026-01-12T08:00:00+08:00,43.2,57.1,0
2026-01-12T08:01:00+08:00,44.8,58.0,0
...
字段识别规则处理方式
时间列，可选timestamp / time / datetime / date / 时间；也可在上传窗口显式指定。验证升序，不自动排序。重复时间戳保留并提示。没有时间列则使用从 0 开始的样本序号。
数值特征除时间与标签外的有效数值列。部分缺失允许；非空损坏数字不冒充缺失。纯文本列忽略并提示。
标签列，可选is_anomaly / label / anomaly / 标签；仅接受非缺失的 0 或 1。仅用于训练段之后的评估及训练污染提示，不筛选训练数据，不调模型或阈值。

时间戳统一存储为 UTC，界面按浏览器本地时区显示。没有明确时区的输入按 UTC 解析并给出提示；建议使用 +08:00 或 Z。示例数据明确携带 +08:00，避免隐式时区改变显示时刻。

系统元数据保留字段不能用作数值特征名：timestamp、is_anomaly、score、threshold、event_id、review_status、review_note、ground_truth。

缺失值只用历史拟合段中位数填充，不做未来插值。历史拟合段中某个变量完全缺失时，运行失败并提示修复数据或调整训练比例。常量特征会被提示；所有历史特征均为常量时 PCA 会拒绝运行。

合成示例

examples/server_metrics.csv 包含 2,400 个分钟样本、6 个相关变量和 5 段人工注入异常。默认前 35% 历史段不含注入异常。列单位、种子和注入区间见 examples/data_dictionary.json；用 python scripts/generate_example.py 可重新生成相同数值。

自动解析不替代数据治理。模型使用样本顺序和窗口，不会自动填补丢失的整行、纠正时间漂移或重采样不等间隔数据。

3. 检测方法、阈值与解释

按时间划分，不随机打散

给定样本数 N、训练比例 r：train_end = floor(N × r)；fit_end = train_end − max(5, floor(train_end × 0.2))。区间均为零基、左闭右开。

  • [0, fit_end)：学习缺失值中位数、均值/标准差和检测模型。
  • [fit_end, train_end)：历史校准段；从该段异常分数的指定分位数计算阈值。
  • [train_end, N)：检测与评估段。异常条件严格为 score > threshold。

训练段不会被标成检测异常。模型假设这段历史主要正常；若已有标签提示训练污染，系统告警，但不会使用标签悄悄删除样本或选择最优阈值。

算法真实计算解释与边界
PCA 重构用历史标准化数据学习主子空间，分数为各变量标准化重构残差平方的平均值。每个变量残差平方构成偏离贡献。目标解释方差不是强制实际方差；最多保留 D−1 个主成分，保证至少一个残差方向。实际保留维数和方差写入解释/报告。落在保留子空间内的异常仍可能漏检。
时序自回归每个变量独立用前 W 个实际观测训练 Ridge，alpha=1；只用 [t−W,t) 预测当前 t。分数为标准化预测残差平方均值。贡献来自预测误差，不是跨变量因果关系。前 W 行因历史不足，分数为 0。对突变敏感；持续平台偏移可能在历史输入适应后漏报。
IsolationForest150 棵树，固定 random_state=42，使用真实模型的负 score_samples，历史分位数校准。特征热力图与份额为历史中位数/MAD 的稳健偏离代理，不是森林内部精确归因。参考曲线为历史稳健中心。

参数

参数默认值允许范围
历史训练比例35%15%–70%
历史阈值分位数99%90%–99.99%
PCA 目标解释方差90%50%–99%，受保留残差方向约束
时序历史窗口8 个样本2–32
最短事件长度3 个样本1–50
合并间隔2 个样本0–20

事件由连续超阈值点形成，允许合并短间隔，再按事件跨度过滤最短长度。间隔中的正常点不会变成逐点异常；事件的跨度与异常点数是两个不同量。结束索引不包含在事件中，结束时间字段表示最后一个包含样本的时间。

贡献份额表示事件区间内某变量累计偏离占全部变量累计偏离的比例。它不是异常概率、模型置信度或故障原因。PCA 重构可能把一个输入变化的残差分配到其他相关变量，不能把排序直接当成注入故障变量的真值。

解释不等于因果。这是用于辅助复核的检测与偏离分析系统，不是自动根因诊断器，不承诺任意领域准确率或论文新颖性。

4. 可视分析、评估与人工复核

  • 异常分数总览：阈值、历史训练阴影、超阈值点；拖动滑块或在图中滚轮缩放，联动变量视图。
  • 变量贡献热力图：在当前范围聚合贡献；点击热力图可切换分析变量。
  • 原始/参考曲线：对比填充后的观测与重构、预测或稳健中心。
  • 事件解释：选择事件后自动定位上下文范围，展示累计贡献与方法说明。
  • 人工复核：待复核、确认异常、误报与备注保存在 SQLite；不修改模型分数，不冒充真实标签。
  • 大数据展示：曲线按分桶峰值采样并保留端点，热力图按区间均值聚合。采样仅影响显示，原始逐点结果与导出不被采样。

有标签时展示精确率、召回率、F1、AUPRC 和事件召回率，仅使用训练结束后的数据，不做 point adjustment。没有标签时不捏造监督指标。评估段没有正例时，召回率/AUPRC/事件召回率按 0 显示，并在报告说明该约定。

标注 CSV 包含原始变量、分数、阈值、逐点异常标记、事件编号和复核信息。HTML 报告不依赖 CDN 或外部脚本，包含配置、真实指标、事件、备注和 SVG 图；用户文本会转义，CSV 文本会防范表格公式注入。

本次升级：诊断、对比与高效复核

  • 数据诊断：原始有效观测统计、缺失比例、采样质量、相关矩阵；常量或不足的相关系数留空。
  • 模型对比：同数据集最多比较三次已完成任务的实际结果和参数；不跨算法比较原始分数。
  • 事件探索：关键词、严重度/状态筛选，峰值/长度排序、分页与批量选择。批量只改结论，保留旧备注；草稿仍需单独保存。
  • 配置与导入：三种参数预设、历史配置复用、真实CSV拖放、限量表头预览与字段映射。
  • 界面：检测完成后收起配置；章节入口直达分析和复核；宽表格支持横向滚动。
  • 性能：线程池解析上传，容量限制及文件更新失效的只读数组缓存。

新增API：GET /api/datasets/{id}/profile、GET /api/runs/{id}/insights、POST /api/runs/{id}/events/review。批量请求传入 event_ids/status 与可选 note，所有事件验证成功才提交。

新版默认端口8767，旧8765服务可同时保留。

数据保存与备份

默认目录 backend/data 包含 chronolens.sqlite3、dataset-*.npz 和 run-*.npz。文件名使用系统 UUID，而不是上传路径。可用环境变量 CHRONOLENS_DATA_DIR 指定隔离目录。先停止服务再复制整个目录，不只复制数据库。运行结果、配置、事件和复核会保留；模型对象本身不被 pickle 持久化。

最多 2 个任务同时运行、4 个等待。中途退出的任务在下次启动时标记失败，不会永久显示正在运行。只运行一个服务实例操作同一数据目录；验证或第二端口请使用不同目录。

默认只绑定 127.0.0.1，适合本地研究和演示。没有登录鉴权，不要直接改成公网服务。迁移部署前需要另行设计鉴权、访问控制、HTTPS 和资源隔离。

8. 常见问题

  • 端口被占用：已有本系统服务会复用；其他程序占用时使用 start.bat --port 8768。不同服务使用不同数据目录。
  • 虚拟环境启动失败：移动过项目或来自其他电脑的 .venv 不能保证可用。先停止服务，移除旧 .venv，再用受支持 Python 重新启动。
  • 没有异常事件：可能数据正常、阈值较高，或最短事件过滤了短异常。查看逐点分数，不把零事件当成模型正确的证明。
  • 时间与 CSV 差几小时：检查时区。无偏移的输入按 UTC；本地显示按浏览器时区。优先提供明确偏移时间戳。
  • 训练段里含故障：模型可能学到异常状态。按实际历史选择主要正常的训练段；不能利用测试标签反复挑“最好”阈值。
  • 如何形成论文：本项目提供完整工程与可复现基线。研究贡献应另行定义，例如区间解释稳定性、人机协同复核效率；需要真实基准、消融和合适的用户实验，不能将模型加图表直接宣称为创新。
